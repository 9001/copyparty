## Commands

```sh
python3 -m venv .venv && .venv/bin/pip install jinja2 strip_hints   # .venv is gitignored
.venv/bin/python -m copyparty -c some.conf        # run from source
.venv/bin/python -m unittest discover -s tests    # all unit tests (~30 s)
.venv/bin/python -m unittest tests.test_shr                # one module
.venv/bin/python -m unittest tests.test_idp.TestVFS.test_1 # one test
./scripts/run-tests.sh          # what the pre-commit hook runs: copies to ./unt, strips type hints,
                                # runs unittest on python2+3, plus smoketest and redup
./scripts/make-sfx.sh fast      # build the single-file copyparty-sfx.py
```

`run-tests.sh` exports `PRTY_NO_VIPS=1`; do the same if libvips is installed and tests misbehave.
Lint config lives in `pyproject.toml` (black 21.12b0, isort, ruff line 120, pylint, strict mypy).

## Code constraints

- The server still runs on **Python 2.7** (and 3.3+, Jython, PyPy). Type hints are stripped at build
  time by `scripts/strip_hints`, so annotations are fine, but no f-strings, walrus, or other
  3-only syntax; the codebase uses `%` and `.format()` formatting. Every module starts with
  `from __future__ import division, print_function, unicode_literals`.
- Only hard dependency is Jinja2; everything else (Pillow, argon2, paramiko, …) is optional and
  imported defensively. Keep new server code dependency-free.
- The web UI is vanilla JS/CSS/HTML in `copyparty/web/` with no build step; translations in
  `copyparty/web/tl/`.

## Architecture

Request path, set up in `svchub.py` (`SvcHub`):

- `SvcHub` owns the singletons: `AuthSrv` (accounts + VFS), `Up2k` (uploads + file index),
  `ThumbSrv` (thumbnails/transcoding), `TcpSrv` (listening sockets), and a broker.
- The broker is `BrokerThr` (threads) or `BrokerMp` (multiprocessing, `MpWorker` per process);
  cross-component calls go through `broker.ask("component.method", …)`, so code must not assume
  shared memory with the hub.
- `TcpSrv` → `HttpSrv` → `HttpConn` (per socket) → `HttpCli` (per request). `httpcli.py` (~8k lines)
  is where almost every HTTP feature lives: query params in `self.uparam` select the action
  (`?ls`, `?share`, `?shares`, `?reload=cfg`, `?th=`…), dispatched from `handle_get` / `handle_post*`.
- FTP/SFTP/SMB/TFTP servers (`ftpd.py`, `sftpd.py`, `smbd.py`, `tftpd.py`) reuse `AuthSrv`/VFS
  for permissions -- an auth change must hold for all protocols, not just HTTP. FTP/SFTP use three
  different lookups: login checks `vfs.aread`/`vfs.awrite`, the top-level listing reads
  `vfs.all_vols`, every other path goes through `vfs.get`. Something mounted outside `aread`
  (grants) therefore fails login yet works by full path.

Accounts and permissions (`authsrv.py`):

- `AuthSrv._reload` parses CLI args + config files (`_parse_config_file`; sections `[global]`,
  `[accounts]`, `[groups]`, `[/volume]` with `accs:` / `flags:`) into a `VFS` tree of volumes,
  each with an `AXS` permission set (`r w m d g G h . a A`).
- `${u}` / `${g}` volumes expand per user/group (`_map_volume_idp`); duplicate mount points are a
  fatal config error.
- Reload happens on `SIGUSR1`, `?reload=cfg`, or a password change; `[global]` changes need a restart.
- Password changes (`chpw`) persist to `chpw.json` as `(user, original_config_pw, new_pw)`;
  `setup_chpw` only applies them while the config still holds `original_config_pw`.
- `AuthSrv.cgen` (`--cgen`) dumps the live config back to config-file syntax (best-effort).

Indexing/uploads (`up2k.py`): per-volume SQLite db (`.hist/up2k.db`, or `--hist`) holds file
hashes and tags; shares are stored in `shares.db` (`--shr-db`). Thumbnails are cached per volume
and generated by subprocess (ffmpeg) or Pillow/pyvips in `th_srv.py`.

Tests build fake servers from `tests/util.py` (`Cfg` = an args namespace with defaults,
`VHttpSrv`/`VHttpConn` = in-memory HTTP) and call `AuthSrv`/`HttpCli` directly; follow
`tests/test_shr.py` or `tests/test_idp.py` for new auth/share tests.
